# TINT 订阅页改为“外部购买 + 统一卡密兑换”设计

日期：2026-05-07

## 背景

当前 `TINT` 前端的订阅页仍保留了“立即升级”“支付宝 / 微信支付”以及 mock payment 跳转等旧语义，但当前真实运营方式已经变成：

- 用户在 app 外购买
- 购买渠道以闲鱼为主
- 运营手动发放卡密
- 用户回到 app 内统一兑换卡密

因此，现有订阅页会误导用户，以为 app 内可以直接支付购买会员或加油包。

## 目标

把订阅页改成与当前真实运营流程一致的形态：

- app 内不承诺在线支付购买
- app 内提供套餐说明
- app 内为不同套餐提供各自的外部购买跳转
- app 内保留一个统一的卡密兑换入口

## 非目标

本次不处理以下内容：

- 不新增 app 内订单系统
- 不新增 app 内支付能力
- 不改动后端卡密兑换接口契约
- 不改动会员/卡密的后台运营逻辑

## 用户流

### 升级路径

1. 用户在 `我的` 页面点击 `升级`
2. 前往 `/subscribe`
3. 在订阅页查看套餐说明
4. 点击对应套餐的 `去购买`
5. 跳转到对应的闲鱼商品链接
6. 用户在闲鱼下单
7. 运营手动发卡密
8. 用户回到 app，在同一页面的统一兑换入口输入卡密完成升级

### 加油包路径

1. 已订阅用户进入 `/subscribe`
2. 选择 `ADDON`
3. 点击 `去购买`
4. 跳转到加油包对应的闲鱼商品链接
5. 用户购买后拿到卡密
6. 回到统一兑换入口完成兑换

### 未订阅用户购买加油包

- 未订阅用户可以看到 `ADDON`
- 但 `ADDON` 的购买按钮必须禁用
- 页面提示：`仅会员可购买加油包，请先升级会员`

## 页面设计

订阅页采用双区结构：

### 上半区：套餐说明与外部购买

展示 `S1 / S2 / S5 / ADDON` 四张套餐卡片：

- 显示套餐权益
- 显示保留策略 / 配额说明
- 每张卡片只有一个主动作：`去购买`

不再出现以下语义：

- `立即升级`
- `立即支付`
- `支付宝`
- `微信支付`
- `安全支付`
- 任何 mock payment 跳转文案

### 下半区：统一卡密兑换入口

页面仅保留一个统一兑换区域：

- 标题：`已有卡密`
- 一个输入框
- 一个兑换按钮

该兑换入口不和任何单个套餐卡绑定。所有会员卡和加油包卡都从这里兑换。

## 交互规则

### Mine 页面

- 当前 `升级` 按钮取消禁用
- 点击后跳转 `/subscribe`

### Subscribe 页面

- 套餐卡的主动作是外跳到闲鱼
- 不再调用 mock payment
- `ADDON` 的购买动作需要校验用户已订阅

### 外部链接策略

采用方案 `C`：

- `S1` 一个闲鱼链接
- `S2` 一个闲鱼链接
- `S5` 一个闲鱼链接
- `ADDON` 一个闲鱼链接

## 配置方案

闲鱼链接采用集中配置，避免散落在组件中。建议使用常量或环境变量，至少包含：

- `S1`
- `S2`
- `S5`
- `ADDON`

页面组件只负责读取并跳转，不内嵌长链接文本。

## 技术改动范围

优先只改最小范围：

- `src/pages/Mine.tsx`
- `src/pages/Subscribe.tsx`
- 如需要，新增一个前端常量配置文件用于保存套餐外跳链接

`src/services/subscription.ts` 中现有 `createOrder` / `mockPayOrder` 可先保留定义，但本次页面不再调用。

## 错误处理

- 如果外部购买链接未配置，对应按钮不应跳空地址
- 建议在开发环境下给出可见报错或 toast
- 如果兑换失败，继续沿用现有兑换错误提示逻辑

## 验证要求

实现后至少验证：

1. `我的` 页面升级按钮可点击并进入订阅页
2. `S1 / S2 / S5 / ADDON` 各自跳正确闲鱼链接
3. 未订阅用户不能购买 `ADDON`
4. 已订阅用户可以点击 `ADDON` 的购买入口
5. 统一兑换入口仍可正常兑换
6. 页面中不再出现 `支付宝 / 微信 / 立即支付 / mock payment` 等误导语义

## 风险与回退

### 风险

- 如果闲鱼链接配置错误，会导致用户跳错商品
- 如果 `ADDON` 的订阅态判断不准，可能出现误放行或误拦截

### 回退

如果上线后需要回退，只需恢复：

- `Mine` 升级按钮旧状态
- `Subscribe` 旧交互

但不建议恢复旧支付文案，因为那与真实运营状态不一致。
